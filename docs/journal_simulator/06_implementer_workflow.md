# 实施者工作流

这一章规定从真实模型复现到完整模拟器结果的推进顺序。实施者不得跳过质量门，不得同时铺开多个未闭环工作负载，也不得用论文数字填补尚未实现的周期。

## 阶段 0：环境与来源清单

创建模型、权重、数据集和工具的 manifest。每项记录来源 URL、许可、提交、校验和、下载时间和可用状态。公开资源由脚本自行下载。缺失的商业工具用开源等价流程替代。

本项目需要的开源工具包括 PyTorch、官方模型仓库、官方 Gaussian rasterizer、gpustat、LPIPS 和开源 Ramulator。由于本项目只评价吞吐，不需要商业存储器编译器、商业功耗工具或商业综合工具。

完成条件是 MVSplat、RealEstate10K 样本、官方权重和目标视图能够在 GPU 上读取。

## 阶段 1：真实功能基线

运行 MVSplat 与 RealEstate10K 的一个官方评测场景。保存官方渲染、Gaussian 参数、PSNR、SSIM 和 LPIPS。固定官方配置后生成 manifest，不为匹配论文数字而改变图像尺寸、视图索引或背景。

完成条件是重复运行产生相同样本清单和数值容差内一致的质量结果。

## 阶段 2：GPU 追踪

在不改变模型数学语义的前提下，记录 S1 至 S4 的真实算子形状、数据依赖、区域位置、候选索引、地址范围和 Gaussian 数量。追踪数据保持在 GPU，按列式分块异步写出。

使用 gpustat 记录利用率。使用 PyTorch Profiler 或 Nsight Systems 检查 CUDA activity 和同步。小时级运行前先完成短片段审计。

完成条件是追踪中的算子总数、张量字节数和官方模型输出能够闭环对应。

## 阶段 3：NoOpt 周期

实现相同硬件上的无优化任务图。NoOpt 执行完整 S1、完整 $D$ 候选深度路径、逐像素 S3 Adaptor 和全部 S4 Gaussian 转换。它不使用论文加速比，也不使用阶段平均延迟。

首先验证单资源周期，再验证一个真实场景的端到端周期。阻塞统计必须能够解释端到端关键路径。

完成条件是同一任务图重复运行周期完全一致，且所有输入输出和 DRAM 事务有来源。

## 阶段 4：单机制上限

依次测量 RMCF、FSDR 和 SAES 在真实 GPU 后端上的端到端上限。每项只删除设计允许删除的工作。若上限低于静态锚点，审计机制无法覆盖的软件阶段，并通过不改变功能输出的工程优化降低这部分时间。

工程优化记录原始时间、改动、输出差异和新时间。任何改变候选、深度或 Gaussian 数量的改动都属于算法，不得记为工程优化。

完成条件是每个单机制的工作量削减、质量和 GPU 时间可分别解释。

## 阶段 5：三项机制周期

按 RMCF、FSDR、SAES 的顺序加入周期后端。

RMCF 完成后，检查矩形合并、边界特征、Pack Buffer 尾部和轻量深度回退。FSDR 完成后，检查签名、CAM 状态、真实候选索引和 DRAM 地址变化。SAES 完成后，先证明替换前后的 L0、L1、Full 标签和任务取消集合逐元素一致，再检查探针 Gaussian、硬归属、覆盖矩、光学厚度守恒和 GGU 反馈延迟。

每项机制完成时更新设计文档、参数来源和实验日志，并创建 Git 提交。

## 阶段 6：全部组合

运行八种机制组合。组合运行重新生成真实功能输出和任务图。检查以下等式。

```text
cycles(main_full_run) == cycles(ablation_mask_111)
quality(main_full_run) == quality(ablation_mask_111)
```

若不相等，停止汇总并修复配置分叉。

完成条件是每个组合均有周期、吞吐、质量和路径统计，且质量不通过的组合被明确排除。

## 阶段 7：工作负载扩展

MVSplat 与 RealEstate10K 完成后，按官方资源可用性扩展。优先扩展同一模型的 ACID，再扩展 TranSplat 和 DepthSplat 的官方支持组合。每次只增加一个模型或一个数据集维度，复用已验证的硬件周期后端，不复制新的模拟器。

不可获得组合保持跳过状态。获得新的官方权重后，从阶段 1 开始补齐该组合。

## 版本管理

当前设计分支为 `journal-python-simulator-redesign`。以下节点必须提交 Git。

1. 设计来源、模块边界和静态锚点完成
2. SAES 固定路径基元重建设计完成
3. 首个真实模型参考运行完成
4. NoOpt 周期闭环完成
5. 每项核心机制第一次闭环完成
6. 八种组合完成
7. 每个新增模型或数据集完成

提交只包含当前节点相关文件。不得提交用户已有的 `transplat` 子模块修改。实验日志在同一提交中更新，不能在结果产生后集中补写。

## 实验日志

每次运行创建不可覆盖的 run 目录，并记录以下内容。

- 当前 Git 提交和工作区状态
- 模型、权重、数据集和样本清单
- 全部配置值及其来源
- GPU、CUDA、PyTorch 和驱动版本
- gpustat 记录和 profiler 摘要
- 周期、吞吐、质量和阻塞统计
- 与静态锚点的差异及解释
- 运行结论和下一步

失败运行也保留日志。只删除确认由下载中断或格式损坏产生的无效缓存，不删除可解释设计问题的负结果。

## 停止条件

出现以下任一情况时停止扩大实验范围并修复当前组合。

- 官方参考质量无法复现
- 周期结果依赖平均阶段时间或论文加速比
- GPU 热路径出现频繁同步
- 小时级任务利用率低于校准包络
- SAES 质量不通过
- All 与消融 111 不一致
- 实测机制上限显著低于静态锚点且无法解释
- 模拟结果显著优于静态锚点上界且缺少任务级证据

质量问题始终优先处理。不得以吞吐结果已经达到目标为理由保留未通过质量门的实现。
